# openmetadata_policy Resource

Manages an OpenMetadata policy. A policy grants or denies a set of operations on entity resources and is attached to roles.

## Example Usage

```terraform
resource "openmetadata_policy" "viewer" {
  name         = "viewer"
  display_name = "Viewer"
  description  = "Read-only access to tables and dashboards."
  enabled      = true

  rules = [
    {
      name        = "view-tables"
      effect      = "allow"
      operations  = ["ViewAll"]
      resources   = ["table"]
      description = "View every table."
    },
    {
      name       = "view-dashboards"
      effect     = "allow"
      operations = ["ViewAll", "ViewQueries"]
      # "All" is the canonical resource for every entity type. It cannot be
      # combined with other resources, and lowercase "all" is rejected.
      resources = ["All"]
    },
  ]
}
```

## Import

Import is supported using the following syntax:

```shell
# Import by UUID.
terraform import openmetadata_policy.viewer 1f6a3a52-8d34-4f4b-9d0f-2f1c1c1c1c1c

# Or import by fully qualified name, which for a policy is its name.
terraform import openmetadata_policy.viewer viewer
```

## Schema

### Required

- `name` (String) Policy name. Changing it replaces the policy, because the name is also its fully qualified name.
- `rules` (Attributes Set) Rules granted by the policy. OpenMetadata orders rules and their operations itself, so this is a set. Updating the set replaces the whole rule set. (see [below for nested schema](#nestedatt--rules))

### Optional

- `description` (String) Markdown description of the policy.
- `display_name` (String) Human-readable name shown in the OpenMetadata UI.
- `enabled` (Boolean) Whether the policy is active. The server defaults this to true.

### Read-Only

- `fully_qualified_name` (String) Fully qualified name. For a policy this equals name.
- `id` (String) Server-assigned UUID.
- `updated_at` (String) Last update time in RFC 3339 format.
- `updated_by` (String) User that performed the last update.
- `version` (Number) Server-side entity version.

### Nested Schema for `rules`

Required:

- `effect` (String) Whether the rule allows or denies the operations.
- `name` (String) Rule name, unique within the policy.
- `operations` (Set of String) Operations covered by the rule, for example ViewAll or EditDescription. The server sorts them.
- `resources` (Set of String) Entity types the rule applies to, for example table, dashboard or pipeline. Use the canonical "All" instead of lowercase "all"; "All" cannot be combined with other resources.

Optional:

- `condition` (String) Optional condition expression that narrows when the rule applies.
- `description` (String) Optional description of the rule.
