# openmetadata_test_definition Resource

Manages an OpenMetadata test definition, the catalogue entry that describes a data quality test: the entity it runs against, the platforms that can execute it, and the SQL it uses.

## Example Usage

```terraform
resource "openmetadata_test_definition" "table_row_count" {
  name                   = "customTableRowCount"
  display_name           = "Custom table row count"
  description            = "Fails when the table has no rows."
  entity_type            = "TABLE"
  test_platforms         = ["Other"]
  data_quality_dimension = "Completeness"
  supported_services     = ["Mysql", "Snowflake"]
  sql_expression         = "SELECT COUNT(*) FROM {{ table }}"
  source                 = "user"
}
```

## Import

Import is supported using the following syntax:

```shell
# Import by UUID.
terraform import openmetadata_test_definition.table_row_count 1f6a3a52-8d34-4f4b-9d0f-2f1c1c1c1c1c

# Or import by fully qualified name, which for a test definition is its name.
terraform import openmetadata_test_definition.table_row_count customTableRowCount
```

## Schema

### Required

- `entity_type` (String) Entity the test runs against: TABLE or COLUMN. The server fixes it at creation, so changing it replaces the definition.
- `name` (String) Test definition name. Changing it replaces the definition, because the name is also its fully qualified name.
- `test_platforms` (List of String) Test platforms that can execute the definition. The server fixes the set at creation, so changing it replaces the definition.

### Optional

- `data_quality_dimension` (String) Data quality dimension the test measures, for example Accuracy or Completeness.
- `description` (String) Markdown description of the test definition.
- `display_name` (String) Human-readable name shown in the OpenMetadata UI.
- `source` (String) Who owns the definition: automation, system, or user. The server fixes it at creation, so changing it replaces the definition.
- `sql_expression` (String) SQL the platform runs for the definition. Required by some platforms, server-side validated.
- `supported_data_types` (List of String) Column data types the test supports, for example INT or VARCHAR. Empty means every type.
- `supported_services` (List of String) Service types the test supports, for example Mysql or Snowflake. Empty means every service.

### Read-Only

- `fully_qualified_name` (String) Fully qualified name. For a test definition this equals name.
- `id` (String) Server-assigned UUID.
- `updated_at` (String) Last update time in RFC 3339 format.
- `updated_by` (String) User that performed the last update.
- `version` (Number) Server-side entity version.
