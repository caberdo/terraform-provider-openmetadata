# openmetadata_storage_service Resource

Manages an OpenMetadata storage service. Storage services are the connection containers for storage containers.

## Example Usage

```terraform
resource "openmetadata_storage_service" "data_lake" {
  name         = "data-lake"
  service_type = "S3"
  display_name = "Data Lake"
  description  = "Storage service for the analytics data lake."
}
```

## Import

Import is supported using the following syntax:

```shell
# Import by UUID.
terraform import openmetadata_storage_service.data_lake 1f6a3a52-8d34-4f4b-9d0f-2f1c1c1c1c1c

# Or import by fully qualified name, which for a storage service is its name.
terraform import openmetadata_storage_service.data_lake data-lake
```

## Schema

### Required

- `name` (String) Storage service name. Changing it replaces the service, because the name is also its fully qualified name.
- `service_type` (String) OpenMetadata service type such as S3, GCS, ADLS, CustomStorage. The server fixes it at creation, so changing it replaces the service.

### Optional

- `description` (String) Markdown description of the storage service.
- `display_name` (String) Human-readable name shown in the OpenMetadata UI.

### Read-Only

- `fully_qualified_name` (String) Fully qualified name. For a storage service this equals name.
- `id` (String) Server-assigned UUID.
- `updated_at` (String) Last update time in RFC 3339 format.
- `updated_by` (String) User that performed the last update.
- `version` (Number) Server-side entity version.
