# openmetadata_dashboard_service Resource

Manages an OpenMetadata dashboard service. A dashboard service registers a connection to a BI tool so its dashboards can be ingested.

## Example Usage

```terraform
resource "openmetadata_dashboard_service" "custom" {
  name         = "custom_dashboard"
  display_name = "Custom Dashboard"
  description  = "Dashboards built in-house and served by the analytics platform."
  service_type = "CustomDashboard"
}
```

## Import

Import is supported using the following syntax:

```shell
# Import by UUID.
terraform import openmetadata_dashboard_service.custom 1f6a3a52-8d34-4f4b-9d0f-2f1c1c1c1c1c

# Or import by fully qualified name, which for a dashboard service is its name.
terraform import openmetadata_dashboard_service.custom custom_dashboard
```

## Schema

### Required

- `name` (String) Dashboard service name. Changing it replaces the service, because the name is also its fully qualified name.
- `service_type` (String) Connector type, for example CustomDashboard, PowerBI or Tableau. The server fixes it at creation, so changing it replaces the service.

### Optional

- `connection_config` (String, Sensitive) Connector configuration as a JSON object string. Its shape depends on service_type and it may contain credentials, so it is marked sensitive.
- `description` (String) Markdown description of the service.
- `display_name` (String) Human-readable name shown in the OpenMetadata UI.

### Read-Only

- `fully_qualified_name` (String) Fully qualified name. For a dashboard service this equals name.
- `id` (String) Server-assigned UUID.
- `updated_at` (String) Last update time in RFC 3339 format.
- `updated_by` (String) User that performed the last update.
- `version` (Number) Server-side entity version.
