# openmetadata_drive_service Resource

Manages an OpenMetadata drive service. Drive services are the connection containers for directories and files.

## Example Usage

```terraform
resource "openmetadata_drive_service" "team_drive" {
  name         = "team-drive"
  service_type = "GoogleDrive"
  display_name = "Team drive"
  description  = "Drive service for the analytics team."
}
```

## Import

Import is supported using the following syntax:

```shell
# Import by UUID.
terraform import openmetadata_drive_service.team_drive 1f6a3a52-8d34-4f4b-9d0f-2f1c1c1c1c1c

# Or import by fully qualified name, which for a drive service is its name.
terraform import openmetadata_drive_service.team_drive team-drive
```

## Schema

### Required

- `name` (String) Drive service name. Changing it replaces the service, because the name is also its fully qualified name.
- `service_type` (String) OpenMetadata service type such as GoogleDrive, SharePoint, Sftp or CustomDrive. The server fixes it at creation, so changing it replaces the service.

### Optional

- `description` (String) Markdown description of the drive service.
- `display_name` (String) Human-readable name shown in the OpenMetadata UI.

### Read-Only

- `fully_qualified_name` (String) Fully qualified name. For a drive service this equals name.
- `id` (String) Server-assigned UUID.
- `updated_at` (String) Last update time in RFC 3339 format.
- `updated_by` (String) User that performed the last update.
- `version` (Number) Server-side entity version.
